1. PREREQUISITES
================================================================================

Hardware:
    - Any modern CPU machine (16 GB RAM recommended for N=100 experiments).
    - GPU is not required; all quantum simulation runs on CPU via Qiskit Aer.

Software:
    - Python 3.11 or 3.13 (3.12 also works).
    - Git (for cloning the repository).

Cloud APIs (optional but recommended for full reproduction):
    - D-Wave Leap account (free academic tier): cloud.dwavesys.com/leap
    - Amazon Braket + IQM device access (for hardware experiments).

================================================================================
2. INSTALLATION
================================================================================

Step 1 — Clone the repository:

    git clone https://github.com/NachoLopezLeis/QuantumCVaRPortfolioOptimization-TFMIgnacioLopez
    cd QuantumCVaRPortfolioOptimization-TFMIgnacioLopez

Step 2 — Create and activate a virtual environment:

    python -m venv eTFM

    Windows (PowerShell):     eTFM\Scripts\Activate.ps1
    Windows (cmd):            eTFM\Scripts\activate.bat
    Linux / macOS:            source eTFM/bin/activate

    Verify: the prompt should show "(eTFM) $".

Step 3 — Install all dependencies:

    pip install -r requirements.txt

    This installs qiskit, qiskit-aer, numpy, scipy, pandas, networkx,
    dwave-ocean-sdk, yfinance, papermill, and all other required packages.

Step 4 — Set up cloud credentials (optional):

    Create a file named ".env" at the project root with your tokens:

        DWAVE_API_TOKEN=your_dwave_token_here

        AWS_REGION=eu-north-1
        AWS_ACCESS_KEY_ID=your_aws_key
        AWS_SECRET_ACCESS_KEY=your_aws_secret
        IQM_DEVICE_ARN=arn:aws:braket:eu-north-1::device/qpu/iqm/Garnet

    If you do not have these tokens, the pipeline runs in fully local mode
    (D-Wave replaced by simulated annealing, no hardware IQAE experiments).

Step 5 — Verify installation:

    python scripts/00_setup_and_smoketest.py

    All checks should print OK. If any fail, re-read the error message
    and check the dependency versions in requirements.txt.

────────────────────────────────────────────────────────────────────────────────
STEP 2 — Universe selection (QUBO)
────────────────────────────────────────────────────────────────────────────────

    # Local (simulated annealing, no token required):
    bash scripts/02_run_universe_selection.sh

    # D-Wave cloud (requires DWAVE_API_TOKEN in .env):
    bash scripts/02_run_universe_selection.sh --dwave

This step:
    1. Computes the 374×374 Pearson correlation matrix.
    2. Builds the Minimum Spanning Tree (MST) using correlation distance
       d_ij = sqrt(2*(1 - rho_ij)).
    3. Detects 11 communities via greedy modularity maximisation.
    4. Computes Pozzi et al. peripherality scores.
    5. Solves the peripherality-maximising QUBO (cardinality K, lambda=500).
    6. Produces three universes: PA (peripheral), PB (central), PC (manual).

Output:
    results/network_selection/selection_report_<timestamp>.json
    results/network_selection/universe_PA.json   (10 tickers)
    results/network_selection/universe_PB.json   (10 tickers)
    results/network_selection/universe_PC.json   (10 tickers)

KEY PARAMETERS (config.yaml)

    qae.epsilon         Precision target.
                        0.005 = standard (used in paper)
                        0.002 = high precision (more queries)
                        0.010 = fast/coarse
    qae.num_distribution_qubits
                        Qubits encoding the loss distribution.
                        4 = 16 bins (standard, used in paper)
                        3 = 8 bins (fast mode)
    qae.use_iqae        Enable IQAE estimator.         Default: true

PHASE 2 — OPTIMIZER:
    optimizer.type              Optimizer type.         Default: adam
    optimizer.learning_rate     Step size.              Default: 0.01

    optimizer.beta2             Adam beta_2.            Default: 0.999
    optimizer.max_iterations    Hard limit.             Default: 500
    optimizer.convergence_threshold  Stop when ||w_t - w_{t-1}|| < threshold.
                                Default: 1e-4
    optimizer.patience          Consecutive steps below threshold.
                                Default: 3

PHASE 2 — NOISE AND ZNE:
    backend.use_noise           Enable noise simulation.  Default: false
    noise_params.two_qubit_gate_error   2Q gate error.
                                A-series: 0 (noiseless)
                                E1: 1e-3, E2: 5e-3, E3: 1e-2
    zne.enabled                 Enable ZNE.               Default: false
    zne.scale_factors           Noise scale factors.
                                B-series: [1, 1.5, 2]
                                D-series: [1, 3, 5]

PHASE 2 — BACKEND:
    backend.type                Simulator.               Default: aer_simulator
    backend.shots               Measurement shots.       Default: 4096
    backend.optimization_level  Transpiler level.        Default: 1

The notebook executes phases in order:
    Phase 0 — Load config, validate, load data, initialise logger.
    Phase 1 — Compute initial CVaR/VaR, build noise model (if enabled).
    Phase 2 — Construct IQAE circuits, estimate subgradient,
               run Adam optimiser, apply ZNE (if enabled),
               compute EVaR and Euler risk decompositions.
    Phase 3 — Run classical baselines (SLSQP, COBYLA, subgradient,
               Monte Carlo, Markowitz, Risk Parity),
               run OOS validation, aggregate all metrics to JSON.

10. UNDERSTANDING THE PIPELINE PHYSICS
================================================================================

This section explains what each component computes, for users who want to
extend or modify the code.

────────────────────────────────────────────────────────────────────────────────
CVaR and its subgradient (src/phase_1/cvar_computation.py)
────────────────────────────────────────────────────────────────────────────────

CVaR at confidence alpha is:
    CVaR_alpha(w) = E[L(w) | L(w) >= VaR_alpha(w)]

where L(w) = -w^T r is the portfolio loss.

The subgradient with respect to w_i is:
    dCVaR/dw_i = -E[r_i | L(w) >= VaR_alpha(w)]

This is what the IQAE circuit estimates.

────────────────────────────────────────────────────────────────────────────────
IQAE circuit (src/phase_2/qae_circuits.py)
────────────────────────────────────────────────────────────────────────────────

The circuit has 4 qubits (n_qubits=4 by default, giving 16 loss levels).

State preparation A loads the empirical loss distribution:
    A|0> = sum_{l=0}^{15} sqrt(p_l) |l>

Grover oracle O_tau marks states where loss > VaR threshold.

IQAE runs Q^m circuits (where Q is the Grover operator) for m=0,1,2,...
and estimates the tail probability a = P(L > VaR) via Clopper-Pearson CIs.

Hardware depth on IQM: depth(m) = 4 + 6*m.
Aliasing occurs at m=3 (depth=22) on both IQM devices.

────────────────────────────────────────────────────────────────────────────────
Adam optimizer (src/phase_2/hybridoptimizer.py)
────────────────────────────────────────────────────────────────────────────────

Standard Adam with simplex projection at each step:

    g_t = IQAE_subgradient(w_t)
    m_t = beta1*m_{t-1} + (1-beta1)*g_t
    v_t = beta2*v_{t-1} + (1-beta2)*g_t^2
    w_{t+1} = Pi_W(w_t - eta * m_hat_t / (sqrt(v_hat_t) + eps))

Pi_W is Euclidean projection onto the simplex {w>=0, sum(w)=1, w_i<=0.35}.

Key property: Adam's second-moment normalization absorbs noise-induced
amplitude inflation, preserving gradient direction even under high noise.
This is why cosine similarity > 0.9999 for all 46 experiments.

────────────────────────────────────────────────────────────────────────────────
Euler risk decomposition (src/phase_2/risk_contributions.py)
────────────────────────────────────────────────────────────────────────────────

For each portfolio weight vector w, the Euler decomposition is:
    RC_i = w_i * dCVaR/dw_i
    sum_i RC_i = CVaR  (exact identity, error < 1e-14 in all 414 cases)

The Herfindahl-Hirschman Index of risk contributions:
    HHI = sum_i (RC_i / CVaR)^2

eff_N = 1/HHI is the effective number of risk contributors.

11. EXTENDING THE CODE
================================================================================

To add a new classical baseline:

    Edit src/phase_3/classical_benchmark.py.
    Add your optimizer in the run_all_baselines() function.
    Return a dict with keys: cvar_loss, weights, iterations, time_seconds.

To add a new noise model:

    Edit src/phase_2/noisemodels.py.
    Implement a function returning a qiskit_aer.noise.NoiseModel.
    Register it in config.yaml under noise_model_config.type.

To use a different quantum backend:

    Edit src/phase_2/quantumbackends.py.
    Implement the QuantumBackend protocol (execute_circuit method).
    Pass it to HybridOptimizer via the backend argument.

12. TROUBLESHOOTING
================================================================================

"No module named qiskit"
    -> Verify (eTFM) is active and the correct Jupyter kernel is selected.

"AlgorithmError in Woerner QAE"
    -> Woerner estimator requires StatevectorSampler (no noise).
       Disable use_woerner when noise simulation is active.

"The job was not completed successfully" in IQAE
    -> IQAE + noise requires TranspilingAerSamplerV2.
       Check qiskit-aer is installed and version >= 0.14.

"CSV not found during data loading"
    -> Run scripts/download_sp500_full.py first.
       The notebook resolves paths from its own directory.

"Experiment takes > 8 hours"
    -> Reduce epsilon to 0.01 in config.yaml.
    -> Reduce num_distribution_qubits to 3.
    -> Disable ZNE (zne.enabled: false).
    -> Disable OOS validation (oos_enabled: false).

"D-Wave returns suboptimal universe"
    -> Increase lambda_2 (cardinality penalty) in the QUBO config.
       Default: 1000. Try 5000 for stricter cardinality enforcement.

"IQM hardware job times out"
    -> Check Amazon Braket device availability (Garnet maintenance windows).
    -> IQM Garnet typical queue: 5-30 min during EU business hours.

"Figures look wrong after re-running"
    -> The SP500 network figure (fig02) uses Kamada-Kawai layout which
       is deterministic given the same data. If the layout changes,
       the underlying correlation data has changed. Re-run step 1.
